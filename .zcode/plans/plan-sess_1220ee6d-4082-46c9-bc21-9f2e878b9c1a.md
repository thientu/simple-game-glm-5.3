# Mobile Fullscreen + Landscape Support

**Problem:** On touch devices in portrait the game is cramped/unplayable. Browsers require a user gesture for fullscreen, and `screen.orientation.lock()` only works while fullscreen — and not at all on iOS Safari.

**Approach:** Request fullscreen + landscape lock when the player taps "Enter the Realms" (or "Rise Again"), and show a "rotate your device" overlay whenever a touch device is in portrait (covers iOS, where locking is impossible). Gate everything to touch devices so desktop stays exactly as-is.

All changes in **`index.html`** (single-file game) + a README note.

## 1. `<head>` meta (line 6)
- Add `viewport-fit=cover` to the viewport meta (so notch areas are usable in landscape).
- Add `<meta name="theme-color" content="#131110">` (matches `--bg`).

## 2. Fullscreen + landscape lock helper (JS, near `startRun()` ~line 1483)
```js
function requestLandscapeFullscreen() {
  if (!touchPrimary) return;                 // touch phones/tablets only
  var el = document.documentElement;
  var req = el.requestFullscreen || el.webkitRequestFullscreen;
  if (!req) return;                          // iPhone Safari: silently skip
  Promise.resolve(req.call(el))
    .then(function () {
      if (screen.orientation && screen.orientation.lock)
        return screen.orientation.lock("landscape"); // Android Chrome; throws on iOS — swallowed
    })
    .catch(function () {});
}
```
- Capture `touchPrimary` next to the existing touch detection (index.html:882-884): `var touchPrimary = !!(window.matchMedia && window.matchMedia("(pointer: coarse)").matches);` — using `pointer: coarse` (primary input is touch) avoids surprising touch-screen laptop users, while `body.touch` keeps governing the on-screen controls as today.
- Wire into the existing listeners at index.html:1493-1494: call it first in the `btnStart`/`btnRestart` click handlers (both are user gestures). The Enter-key start path stays desktop-only, untouched.

## 3. "Rotate your device" overlay (portrait fallback for iOS)
- **HTML:** new `<div id="rotateHint">` after `#touchUI` (~line 325) — dark vignette backdrop, gold serif text "Rotate your device", animated phone-rotates-90° CSS/SVG icon, matching the game's Diablo-style aesthetic.
- **CSS:** hidden by default; shown purely via media query, no JS state:
```css
#rotateHint { display: none; position: fixed; inset: 0; z-index: 60; /* above overlays */ }
@media (orientation: portrait) { body.touch #rotateHint { display: grid; } }
```
This covers menu and gameplay — on Android the lock works so it's rarely seen; on iOS it's the enforcement mechanism.

## 4. Auto-pause when rotated to portrait mid-game
- Listen to `matchMedia("(orientation: portrait)")` change (with `addListener` fallback for older iOS): if `body.touch` and state is `play`/`intermission`, call the existing `pauseGame()` (index.html:1463). Prevents dying while the phone is mid-rotation.

## 5. Landscape / safe-area layout tuning
- `#tracker` (line 189): offset by `env(safe-area-inset-top/right)`; `#miniStats` (line 239): `env(safe-area-inset-left)`; `#hudBottom` (line 206): `env(safe-area-inset-bottom)` — keeps HUD clear of notches in landscape.
- `#touchBtns` (line 260): add `@media (orientation: landscape)` rule moving the cluster into the bottom-right corner (`right: max(14px, env(safe-area-inset-right)); bottom: calc(14px + env(safe-area-inset-bottom))`) — vertical space is scarce in landscape, and the centered HUD bar leaves the corners free on wide screens; shrink buttons slightly (~56px, attack 66px).

## 6. README
- Short note: on touch devices, tapping "Enter the Realms" goes fullscreen and locks landscape; portrait shows a rotate prompt (iOS limitation).

## Verification
- Serve locally (`python3 -m http.server`) and use browser automation with an emulated mobile viewport:
  - Portrait + touch: rotate overlay visible, blocks screen; landscape: hidden.
  - Tap "Enter the Realms" with touch emulation: `requestFullscreen`/`orientation.lock` invoked (can't fully execute in emulation, but code path + no desktop regression verified).
  - Desktop viewport: no fullscreen call, layout unchanged.
- Canvas needs no changes — the existing `resize()` (index.html:444-461) already re-fits on rotation/fullscreen since `resize` fires.
